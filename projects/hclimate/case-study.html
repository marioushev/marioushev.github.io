HClimate — building sensor data, made legible

A dashboard for managing and visualising building IoT datasets — turning thousands of raw sensor readings into views a facilities team can actually act on, without the browser grinding to a halt.

01 / the challenge

Too much data, not enough signal

Connected buildings emit a constant stream of sensor readings — temperature, humidity, and the state of devices across many buildings. On their own the raw numbers are noise; a facilities team needs to see what matters at a glance and drill in when something looks off.

The hard part is volume: rendering and filtering thousands of readings the naive way freezes the UI. The dashboard had to stay responsive while crunching large datasets in the browser.

02 / our role

A fast front-end with the heavy lifting moved off-thread

We built the React single-page app and its two core views, and moved the expensive data work into a background Web Worker so the interface never stutters.

  • React SPA (Vite)
  • Buildings overview
  • All-devices view
  • Web Worker data pipeline
  • Charts & visualisation
  • Performance tuning
03 / the work

Two views, one off-thread data pipeline

The app centres on two views — a Buildings overview and an All-devices breakdown — backed by a dedicated Web Worker that parses and aggregates the raw dataset off the main thread. The UI only ever receives ready-to-render results, so scrolling and filtering stay instant even on large datasets.

data flow — heavy work stays off the main thread
main thread (React UI)
   │  postMessage(rawDataset)
   ▼

   │  postMessage(viewModel)
   ▼
render  <BuildingsView />   ·   <AllDevicesView />
        // UI receives ready-to-render results only → no jank
